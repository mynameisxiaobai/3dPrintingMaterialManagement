## 耗材库存「色系折叠」视图重构 → 色系手风琴

**背景**：旧的 `web/filament-manager.html` 色系视图是「文件头瀑布流 + 鼠标静置 120ms 翻盖弹出绝对定位抽屉」，
用户明确不要 hover 展开、要求文件夹缩小、内容以更小形态常驻展示、点击才看详情。
经四轮迭代留下的 hover 状态机（`famPointerUpdate`/`famSchedule`/halo/`famLocked`）全部删除，
约 400 行 JS + 280 行 CSS。

**新形态**（用户从三个方案里确认的）：
- 单列手风琴 `.fam-list > .fam-grp`，标题行 46px 常驻：`.fam-rail` 族色左轨 + `.folder-name` +
  `.folder-meta`（卷/色/kg/低库存）+ `.fam-ribbon` 实时色带 + `.fam-caret`。
- 折叠动画用 `grid-template-rows: 0fr → 1fr`，三层结构（外层轨道 / `.fam-body-clip` 裁剪带
  `min-height:0` / `.fam-cards` 放 padding）。**padding 放中层会漏出死条**，实测已验证 0px。
- 内容默认「迷你卷」`.spool-chip`（26px 色块 + 名称 + 卷数 + 品牌·材质），点击弹锚定浮层。
- 密度两档 `fmFamDensity`（`mini` 默认 / `card` 复用 `filamentCardHtml`），裸字符串存本地，
  不进 `FM.SYNC` / `DM_STORE_KEYS` / 服务端 `SYNC_KEYS`（与 `fmTheme` / `fmDefaultView` 同路线）。
- 锚定浮层 `#spoolPop`（`position:fixed; z-index:150`，JS `openSpoolPop`/`closeSpoolPop`/`placeSpoolPop`），
  **必须是 `#famView` 的兄弟节点**，因为 `renderFam` 用 `innerHTML` 整体重建。

**状态模型**：`const famCollapsed = new Set()`（存反例，缺省展开）；`toggleFam` 拒绝收起
`colorFamFilter` 命中的组（否则统计页 `stJump('family')` 跳过来落在折叠组上）。

### 踩到/验证过的坑（跨项目适用）
1. **不能复用 `handleCardClick`**：它首行 `if (e.target.tagName === 'BUTTON') return`，
   而 `.spool-chip` 本身就是 `<button>` → 复用会让点击永久失效。
2. **`updateAllVisuals()` 必须同步改**：`toggleSelectAll` 只走它，漏了就是「按钮数字跳到 200，一格都没变色」。
   `clearSelection` 也从 `forEach(updateItemVisual)` 改成一次批量刷。
3. **浮层三条关闭路径要分开处理**：外部 `pointerdown` 遇 `.spool-chip` 要放过（否则 pointerdown 先关、
   同一手势的 click 再开 = 「关不掉/闪一下」）；`scroll` capture 要 `pop.contains(target)` 放过
   （否则滚自己内容就关）；开时 `focus({preventScroll:true})`（否则滚页面 → 触发上一条自杀）。
4. **首帧定位**：先 `visibility:hidden` + `display` 再量 `offsetHeight`，否则闪一下左上角。
5. 色带宽度**不要用 flex-grow 撑满**，会变成进度条压过数字；改成「1 卷 = 10px，最少 14px」的自然宽度，
   且 `margin-left` 紧跟数字（推到行尾时单色系只剩一个小色片孤零零挂着）。
6. Esc 处理：默认全展开后「有 `.open` 就 `famCollapseAll()`」= 一按整页塌；改成只收焦点所在组，
   并把焦点还给该组标题行（内容已 inert）。

**测试**：删 `tests/check-hover.js`、`tests/visual-hover.js`；`tests/check-views.js` 第 5 章之后整段重写
（它是单个大 `try`，一处 ReferenceError 会让后面 300 行全不执行）；新增 `tests/visual-spoolpop.js`
（playwright 真实几何：hover 零变化、浮层四边在视口内、翻边、五条关闭路径、折叠后高度归零）。
全量 13 个测试文件 + visual 21 项全绿。

**README** 第 38 行与第 262 行的架构描述同步更新。

## 追加：色系手风琴 → 色系墙（同日第二次重构）

**触发**：用户「想在一个界面上尽量展示多的色系，可以多个卡片的形式展示嘛？」——
上一版的单列 12 行竖排纵向太长。确认三项：4 列 / 卡宽 315px、溢出用「限高 + 点卡放大成整行」、
卡内沿用迷你卷并保留「迷你 / 卡片」密度。

**最终形态**：
- `.fam-list`（flex column）→ `.fam-wall`（`repeat(auto-fill, minmax(min(100%,292px),1fr))`），
  1304px 内容宽正好落 4×315.5，12 个色系 4×3 一屏看全（实测 offsetTop 3 行，总高 ~940px）。
- 卡片外壳 `.fam-grp` 接管描边/圆角/`overflow:hidden`；`.fam-hd` 降级为卡内 header 条
  （删 border/radius/bg，`focus-visible` 改 `outline-offset:-2px`，否则焦点环被 overflow 裁掉）。
- 卡头砍掉 `.fam-ribbon` 与「色数/克重」：315px 里只剩 40–70px，色带必被切成 1–2 段。
  族色只留 `.fam-rail` 一根 3px 轨，`.is-expanded` 才染边（12 个彩框会很花）。
- 卡内 chip 加紧凑变体：swatch 26→18、双行 44→单行 32、隐 `.chip-meta`（142px 格放不下）。
  **纯 CSS 改，markup 不动** → `updateItemVisual` / `spoolChipClick` / `updateAllVisuals` 零改动兼容；
  面板里的 chip 不在 `.fam-grp` 下，自动恢复 44px 双行。4 行 chip = 146px，卡 ≈ 218px，
  3 行墙 ≈ 682px —— 这是「一屏看全 12 个色系」能否成立的硬约束，改回 44px 立刻崩。
- 截断 `famCap()`：`FAM_CAP = { mini:{compact:4,default:8}, card:{compact:1,default:2} }`，
  两套独立映射（不能共用一个「行数」，card 单卡本身就 206–270px）。
- 顶栏 `[迷你|卡片] | [紧凑|标准]`，两个键 `fmFamDensity` / `fmFamRows` 都是设备本地裸字符串。
- 状态机 `famCollapsed`/`isFamOpen`/`applyFamOpen`/`toggleFam`/`famCollapseAll`/`famExpandAll` 全删。

**核心难点：点卡放大成整行怎么实现**
- `grid-column:1/-1` 直接跨列 **不行**：auto-placement 会把非行首的卡挤到下一行行首，
  卡片从第 2 列「飞走」、周围全部重排。
- 纵向撑开 **不行**：同排其他卡只有 218px，撑开的卡旁边留一大片空白。
- **解法：单例 `.fam-panel`**，`.fam-wall` 的直接子元素 + `grid-column:1/-1`，
  JS 用 `insertBefore` 插到「被点卡所在行的**下一行第一个卡**」之前。其他卡只被整体下推。
- 行判定必须用 `offsetTop`，**不能用 `getBoundingClientRect().top`**：
  卡片有 `@keyframes fadeIn` 带 `translateY(6px)` 且 delay 各异（0.024s/张），
  rect 含 transform，渲染后 0.6s 内同行能差 6px。offsetTop 不受 transform/滚动影响且同行严格相等。
- 插入位置只由「卡片 DOM 顺序 + offsetTop」决定、与面板自身高度无关 → 无重排循环。
  **不要给面板挂 ResizeObserver**。

**又踩到的坑**
1. `.fam-body{display:grid}`（折叠动画遗留）会盖掉 UA 的 `[hidden]{display:none}` → 内容收不起来。
   删折叠 CSS 时顺手解决，并加了断言 `12.5b` 防回归。
2. `@supports not (grid-template-rows:0fr)` 降级块**不是「留着无害」**：它把 `.fam-body-clip`
   设成 `display:none`、只在 `.fam-grp.open` 时显示；折叠态没了就永远没有 `.open`，
   旧引擎上内容永久消失。必须删。
3. **编辑模式必须忽略 cap**：`toggleSelectAll` 会选中全部，只渲染前 N 条就是
   「数字跳到 200、一格都不亮」——`updateItemVisual`/`updateAllVisuals` 只遍历 DOM 里存在的 chip。
4. 「还有 N 卷」的单位是**卷数之和**不是 `items.length`：一条记录 `qty` 可能是 5。
5. 卡片有了 `overflow:hidden`，`outline-offset` 必须为负。
6. 两组分段控件都用 `.on` → `querySelector('.on')` 会命中错的那个，测试 9.6 直接炸；
   给两组分别加 `data-famdens` / `data-famrows`。
7. `$$(...)` 返回数组，取 `.textContent` 得 undefined（我把 9.6c 写错过一次）。

**接线**：`renderAll` 开头 `closeFamPanel()`（覆盖搜索防抖 / prnSlicedSweep / AMS 轮询）、
`applyView` 开头也调（`renderAll` 在非 fam 视图下不重建 `#famView`，切换会留旧面板）、
Esc 顺序改成 spoolPop → colorFilterPanel → famPanel → sw-dd → modal、
`stJump('family')` 在 `flushSearch()` 之后 `openFamPanel(name)`（不能塞进 `renderFam`）。

**测试**：`check-views.js` 从 193 → **235** 项（第 5、6 章整段重写为面板断言；
新增编辑模式不截断 7.12-7.15、行档映射 9.12-9.20、防复活 12.41-12.44）。

「同排后面的卡仍在原行」——这是「行中间插入」bug 的唯一回归网。

全量 13 个测试文件 + 浏览器 31/31 全绿。
