## 色系墙：折叠面板 → JS 打包的瀑布流砖墙

用户三个要求：① 全部展开、不许截断（"必须点击才能展示"是痛点）；② 卷多的色系横向加宽、卷少的保持竖向；
③ 用瀑布流算落位，"尽量不要有空隙"。

**最终形态**：每个色系一块砖，砖身永远渲染全量，砖头 `<h3>` 无第二层可展开；
落位由 `packFamWall()` 现算，`.fam-wall` 只在加上 `.is-packed` 后才让砖 `position:absolute`。

### 算法的三处关键判断

1. **加宽判据用高宽比，不用卷数**。`FAM_ASPECT = {mini:1.6, card:2.0}`，砖高 > 宽×上限就加宽一档。
   两档不同值是必须的：迷你卷一格 32px，窄砖能装 12 卷才 190px；完整卡片一张就 230px，
   同样 1.6 倍的话 2 卷的色系（≈490px）会被无脑加宽，墙上全是横砖。
2. **落位分 = `top + 空洞`**，空洞 = 跨 s 列盖住的「各列最高值 − 最低值」× span。
   只按 top 最小选位的版本实测把蓝系落在 `colH=[2054,2612]` 之间，左列空出 **460px**（比砖还高）。
3. **降级判据**：若这个落点必然留洞（> `FAM_HOLE_TOL` 40px）且**竖放不会把墙顶得更高**，就退回 1 列。
   修完后实测空洞合计 **0**，四列底边 366/404/480/366。

### 四个踩过的坑

- **`data-span` 不能在量高循环里写**：循环里先写 1 再写 2，降级回 1 列时 CSS 的 `[data-span="1"]`
  规则（隐藏色带/克重）就不生效了。必须挪到循环结束后按最终值写一次。
- **测量的顺序约束**：先写 width 再读 `offsetHeight`；量完所有砖才统一定位；位置全写完才加 `.is-packed`。
  顺序错了要么量到上一条的宽，要么墙高算错。
- **禁止给砖挂 ResizeObserver**：砖高受自身宽度影响，观察自己写自己 = 自激。
  改用 `resize` → `requestAnimationFrame` 合并 + `document.fonts.ready` 补一次。
- **2 列时不能加宽**：`maxSpan = cols >= 3 ? min(cols,2) : 1`。2 列加宽 = 独占整行，砖墙退化成一条条横幅，
  而且横砖得等两列齐平才能落位，等于把瀑布流压回堆叠。浏览器级测试 7l 抓到了这条。

### 数据管理页的空白

根因是 `.st-cards` 用 CSS grid，同一行两张卡被最高那张拉齐 → 矮卡下方死白。
改成 `.dm-cols{grid-template-columns:1fr 1fr}` + 两个 `.dm-stack{display:flex;flex-direction:column}`：
栏内首尾相接，永不留洞。回收站移出两栏单独整行。
实测左栏 798 / 右栏 603 / 回收站 1304，只剩两栏自然收尾差 ~145px（不是缺陷）。
注意 `#dmStoreCard` 量出高度 0 是正常的——它 `display:none`，只在服务端存储模式下才显示。

- `visual-spoolpop.js` 31 → **32**：⑦ 节换成瀑布流几何验收（两两重叠 / 列内空洞 / 墙高对齐 /
  `chips === SEED.length` / 红系 span=2 / 宽砖宽 ≈ 2 列 / left 对齐列网格 / 缩到 720 后仍无洞）

**README** 第 38 行功能表 + 262-270 架构段重写（`packFamWall` 三段式、`famFlash`、删掉 famCap/famPanel 的描述）；

- 瀑布流底边必然参差（各列底边 366/404/480/366），这是 masonry 的固有代价，内部空洞才是能消除的。

- `.fam-hd` 从 `<button>` 改成 `<h3>`：没有可展开的第二层，做成按钮是假入口（无障碍问题）。

## 第二轮：卡宽统一 + 吸顶工作台 + 回到顶部

用户三条：① 卡片密度下各色系大小不统一，看着乱；② 库存页顶部要冻结；③ 色卡库同上；④ 每页加浮动返回顶部按钮。

### 卡宽不统一的根因与取舍

截图里红系是 2 列宽砖（730px）里塞 3 张 228px 的卡，旁边棕系是 1 列砖里 338px 的卡 ——
**卡片是按砖宽 1fr 填满的，砖一宽卡就宽**。所以「横放」和「同宽」在卡片密度下互斥。

取舍：**加宽只对迷你密度开放**（`maxSpan = (famDensity !== 'card' && cols >= 3) ? 2 : 1`）。
迷你格子是「按行均分」，砖宽 385→785 只是从 2 列变 5 列，格子宽度只差 17%（148~179px）；
卡片是「整张缩放」，同样的加宽差 59%。代价：卡片密度下卷多的色系只能往下长（高矮不齐可接受，宽窄不齐不行）。
实测 190 张卡只有 1 种宽度（294px），12 块砖同宽（316px）。

### 吸顶栈：三层相加，不能都写 top:0

`header`(0) → `.page-tabs`(`--chrome-h`) → `.pinned`(`--chrome-h + --tabs-h + --tabs-gap`)。

- **两个高度必须实测**：≤720px 时 header 的按钮组变 4 列网格，整条从 60px 涨到 127px，
  写死 60 会让页签钻到 header 底下。`paintChrome()` 用 `getBoundingClientRect().height` 写 CSS 变量，
  `ResizeObserver` 盯 header/页签（resize 事件抓不到「窗口没动、header 换行了」）。
- **页签与工作台之间的 18px 缝隙会透出内容**：给 `.page-tabs` 加 `box-shadow: 0 var(--tabs-gap) 0 var(--bg)`，
  用同色实心阴影把那一条填上，不动布局。实测滚动到 620px 时缝隙干净。
- **紧凑态**：滚动 >120px 把 5 张 96px 的统计卡压成 5 个 34px 胶囊。用同一套 DOM + flex，
  标签不删只缩（删了「27」就不知道是几卷还是几克）。`stats-bar` 从 `auto-fit` 改 `display:flex`，
  否则 5 个胶囊被拉满整行、标签和数字分在两头，读起来像表单。
- **窄屏不冻工作台**（≤900px）：手机 header 已占 127px，再叠统计+工具栏只剩半屏。页签继续吸顶。
- **`.pinned` 绝不能有 overflow**：祖先有 overflow 会让 sticky 直接失效（已写静态断言 12.56 锁住）。
- `is-stuck` 用「阴影 + inset 发丝线」：纯投影在暗色下是黑压黑，等于没画。

### 回到顶部

阈值从 480 降到 **320**：480 在「一屏半」的页面上永远够不到（实测 maxScroll 只有 180~446），
按钮等于没做，而那种页面恰恰最需要回顶。
隐藏用 `visibility` 不用 `display`（display 会在获得焦点时突然蹦出来，也不该进 tab 序）。
`jumpTop` 受 `prefers-reduced-motion` 约束，并把焦点交给 `#main`。

### 测试

- `check-views.js` 220 → **236**：12.49 改写（迷你+3列才算加宽）、12.50-12.66 覆盖吸顶三层/紧凑态/窄屏/FAB/结构包裹
- 新增 `tests/visual-sticky.js` **36 项**浏览器级验收（三层吸住、紧凑态变矮、FAB 显隐与点击、卡宽唯一、
  迷你仍加宽、色卡库 hero 正常滚走、390px 不冻）
- 全量 13 个 node 测试 1160 断言 + 2 个视觉测试（32 + 36）全绿

### 踩到的测试坑（值得记住）

- **夹具太短会让断言假失败**：页面 maxScroll 只有 446px 时，`scrollTo(0,900)` 停在 446，
  按 480px 阈值判 FAB 就是「没出现」。桌面高度 900 时文档要 >1200 才滚得动。
- **`document.querySelector('.pinned')` 会命中文档顺序靠前的隐藏页**，rect 全 0，
  「吸住了没」断言会 0→0 假通过。必须 `querySelector('.page.active .pinned')`。
- 首屏三层是「依次在下方」（中间有 main 的上内边距），不是紧贴；断言要写 `>` 不是 `≈`。

### ① 工具栏压成一行

6 组 20 多个筛选按钮全部铺在吸顶区里要占两整行。改成：工具栏只留

原来它 `/filter-btn danger/` 紧挨着「已用完」—— 隔两像素就是误删入口。

### ④ 批量条吸底

`#batchBar` 从 `#invPinned` 里搬出来，放到 `</main>` 之后与 `#toTop` 同级：
```
position:fixed; left:50%; bottom:18px; transform:translateX(-50%); width:min(760px, calc(100% - 150px))
```
- 限宽 760 居中（通栏会散成一条空旷横带）；两侧留 150px 是因为 `#toTop` 在右下角。
- `body.batch-on` 两个作用：`main { padding-bottom:110px }`（否则最后一排永远被压住）+
  `.to-top { bottom:92px }`（否则两个贴右下角会叠）。
- 窄屏（≤720px）改贴底通栏 + 隐藏「取消选择」（顶部有「退出编辑」兜底）。

`switchPage` 末尾 `window.scrollTo(0,0); paintPinned();`。
`stJump` / `stJumpMatrix` 在 switchPage 之后自己再滚，顺序上覆盖归零，不受影响。

### ⑥ 卡片底栏换两个真数字

`1 ×1000g · 有料盘` → `库存 2.0kg | 90天 320g`。
- 规格（×1000g）是录入时固定的常量，重复一百遍不产生决策价值，退到 `title` 里。
- 「有料盘」是默认态，不占地方说话；无料盘的卡左上角本来就有红角标。

- **窄屏必须改竖向**：卡片 150px 宽、两格各 75px、扣掉内边距只剩 47px，「库存 0.00kg」横排
  一定会被省略号截掉（实测截成 `0.0…`）。`@media (max-width:560px)` 下改 `flex-direction:column`。

### 顺带修掉的真 bug：renderAll 把滚动位置吃掉

`renderAll` 清空 `#famView/#gridView` 的 innerHTML 时，页面瞬间塌成几百像素高，
浏览器立刻把 `scrollY` 夹到 0，之后再也回不来 —— 表现是**勾选一张卡片，页面自己跳回顶部**
（实测 70 条时能跳掉一屏）。批量条吸底就是为了「选中第 50 卷时还能看见按钮」，
勾一下就跳顶的话那条吸底白做。修法：进函数记 `keepY`，渲染完只在「确实变小」时补回。

## 色系砖头重设计（同日，第四轮）

用户反馈两点：**顶部色系名称不明显**、**不同色系之间区分不明显**（附移动端与桌面截图）。

### 根因（不是"颜色不够鲜艳"，是三个小问题叠加）

1. 族色只有一个出口：`.fam-rail` 3×20px 的细线。在 46px 高的砖头里，3px 宽基本看不见。
2. 12 块砖共用同一个 `--bg-2` 中性底 + 同一种 `--border` 淡边框 —— 扫视时连成一片白卡。
3. 标题 `0.9rem/600` 且 `letter-spacing: 0.12em`。**中文正文/标题拉字距只会把词稀释成
   几根散开的笔画**，加上「红色系」三字同权重，眼睛没有落点。

### 做法：砖头 = 色系标牌（三重标识）

```css
.fam-grp { border: 1px solid color-mix(in oklch, var(--fam) 24%, var(--border)); }
.fam-hd  {
  height: 52px;
  background: color-mix(in oklch, var(--fam) 16%, var(--bg-2));
  border-bottom: 1px solid color-mix(in oklch, var(--fam) 26%, var(--border));
  box-shadow: inset 0 3px 0 var(--fam);   /* 顶线，inset shadow 自动跟随外壳圆角 */
}
.fam-rail { width: 5px; height: 26px; }   /* 原 3×20 */
.folder-name { font-size: 1.02rem; letter-spacing: 0.01em; }  /* 原 0.9rem / 0.12em */
.fam-suffix { font-size: 0.63rem; color: 弱化的 text-3; }     /* 「色系」二字降级 */
```

- **染色比例是量出来的，不是拍的**：11% 时 12 块砖头实测 oklch L 全落在 0.94–0.98、
  chroma 0.004–0.024，肉眼无法区分；16% 后 L 拉到 0.87–0.985、chroma 最高 0.028，才有色调差异。
  再高会压掉文字对比，且深色族（黑系）会先变灰。
- **顶线 2px → 3px**：2px 在 1440px 整图缩略时看不出来。
- 删掉 `.fam-hd:hover { background: var(--bg-3) }` —— **它不是可点元素**，换底色是骗人。
- `data-span="1"` 的窄砖也能看到标牌（不依赖 ribbon）。

### 白色系必须特例（重要）

`#f2f2f2` 按 16% 混进近乎纯白的 `--bg-2` 仍然是白 —— 数学上无解，不是参数问题。
强行给白系上色（比如调深 `SW_FAM_COLOR.白`）会污染颜色筛选面板里那个白点。
正确做法是**换成描边表达**：

```css
.fam-grp[data-fam="白"] { border-color: var(--border-hi); }
.fam-grp[data-fam="白"] .fam-hd { box-shadow: inset 0 3px 0 var(--border-hi); }
```

白/灰/黑三块在浅色主题下的砖头 L 分别是 0.985 / 0.944 / 0.874，明度递进刚好区分开，
不需要再给灰/黑特例（它们混出来本来就有差）。

### 系名拆结构的两个约束

```js
const famLabel = g.fam === FAM_UNSET
  ? `<span class="folder-name"><span class="fam-main">未设色</span></span>`
  : `<span class="folder-name"><span class="fam-main">红</span><i class="fam-suffix">色系</i></span>`;
```

- `.folder-name` 从纯文本变成 flex，**ellipsis 必须下沉到 `.fam-main`** ——
  父级 `overflow:hidden` 对 flex item 里的文本不生效。
- `textContent` 拼起来仍是「红色系」，`11.22` 那条断言与朗读口径都不用改。
- 「未设色」不挂「色系」后缀，否则读成「未设色色系」。

### 测试

- `check-views.js` 258 → **266**：12.18a–12.18h 锁住染色比例、顶线、砖框、色标尺寸、
  字号/字距、后缀结构、未设色不挂后缀
- 12.18 从 `46px` 改为 `52px`（旧断言会挡住这次改动，正是它的作用）
- 13 个 node 测试 **1190** 断言 + 3 个浏览器测试（32 + 36 + 41）全绿
- 截图核对：浅色 4/3/2 列、卡片密度、暗色、移动端浅色与暗色

### 关键决策

1. **色卡库分组折叠**：`SW_GROUP_PREVIEW = 12`，组标题内部 sticky。
   卡片仍用**全局** `data-i`（不是组内序号），否则 `openSwModal(i)` 会指错人。
   30227px → **7067px**，节点 9382 → 2090，卡片 692 → 144。
   搜索时 `forceOpen`（用户已在缩小范围，不该再藏）；只有一组且 ≤12 张时不画组头。
2. **组标题的 sticky top 需要 `--pinned-h`**：色卡库工作台高度会随「已选筛选」胶囊条变，
   写死 46px 会露卡片。用 `ResizeObserver` 观察所有 `.pinned`，在回调里取 `.page.active .pinned`
   的高度写变量（隐藏页触发也只是重算当前可见的那个）。
3. **品牌名录搬到 hero 弹层**：底部 400px 的常驻网格在 3 万像素处，等于不存在。
   弹层管焦点进出（`swBrandPrevFocus`），Esc 关闭。
4. **统计页删掉「当前口径合计」KPI**：`stVal` 只由 qty/finished 决定，默认范围下它和
   「库存卷数 / 库存重量」是**同一个数**，8 张卡里有一张纯重复。删掉后 7 张各 178px。
   `stScope !== 'remain'` 时才补回来（那时它才有独立含义）。
5. **配色语义**：`ST_PALETTE[排序后的下标]` → `stNameColor(名字)`。改口径/换筛选会重排，
   以前同一个品牌每次都换个颜色。品牌查 `brandDB` 位次、材质查 `ST_MAT_ORDER` 枚举，
   哈希只做兜底（5 个名字落 16 槽会撞）。
6. **交叉表改点阵**：去掉满格边框，零值不画「–」也不填色，有值染 accent。
   热度给**两个**变量 `--heat` / `--heat-d`（38%）—— 浅色 accent 是深青（46% 明度），
   深色 accent 是亮青（72%），同样比例在暗色下会把数字淹掉，不能共用一套。
7. **数据管理重排**：存储只列非空 + 「其余 N 项为空」折叠；整理与修复搬到右栏，
   两栏 411 / 528（差 117），危险操作回到右栏底部 y≈822（首屏内）。
8. **打印机离线折叠**：`#prnDataArea` / `#prnOfflineData` 二选一；
   离线时 hero 的「刷新」也藏（`refreshBtn.hidden = !printerOnline`）；
   加「设备与连接 / 对账与流水」两个分区标题；9 处内联 `margin-top:16px` 收到容器层。
9. **深色页签** `--text-3`(48%) → `--text-2`(68%)，hover 用 `--text-1`。
10. **hero 统一**：删掉 `.sw-hero`（1.45rem 标题），四个页面共用 `.st-hero`（1.12rem / 660px）。
    注意注释里仍会提到 `.sw-hero` 字样，测试断言要用 `.sw-hero-title` / `class="sw-hero"` 判。

### 踩到的坑

- **`.st-card-head` 加 `flex-wrap: wrap` 不会换行**：标题和 spacer 都是 `flex:1`，
  容器先把它们压到极限（标题 86px），永远轮不到换行。必须让标题 basis 吃整行：
  `flex: 1 1 calc(100% - 40px)` + `spacer { display: none }`。
- **`#dmStorage .dm-kv` 数出 16 行**：折叠起来的空项也在 DOM 里，`querySelectorAll` 全选中，
  必须按 `offsetHeight > 0` 过滤才是「看得见的行」。
- 程序化 `element.click()` 不会把焦点移到按钮，`activeElement` 仍是 body —— 测焦点回流要先 `focus()`。
- `visual-sticky.js` 里 `document.querySelector('.sw-hero')` 会因这次重构成 null，改 `#pageSwatch .st-hero`。
- `.dm-kv` / `.st-table td` 的 `border-bottom` 原来硬编码 `oklch(24% 0.012 240)`（暗色线），
  浅色主题下是一条深灰 —— 顺手换 `var(--border)`。
