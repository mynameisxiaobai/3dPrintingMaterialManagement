## 卡片色块「悬停液体洪水」（WebGL 单例 canvas）

用户指着库存页卡片截图问：能不能保持初始颜色不变，只加一个 useplanes `shader-flood` 那样的悬停动效。
该组件是 Planes 的 Pro 付费件（`npx shadcn add @useplanes/shader-flood` 要 license），**源码拿不到**，
按它公开的原理（单 fragment shader、离屏即暂停、每张卡一套配色）自写了一份等价实现。

### 用户拍定的范围
只染顶部 100px 色块区（不碰文字区）／同色深浅三阶（不换色相）／只铺网格视图 + 色系墙卡片密度。

### 架构：全站一个 canvas，悬停时移进那张卡
`renderAll()` 整段替换 innerHTML，且 200 条数据时 `#gridView`（隐藏）与 `#famView`（可见）
**同时各有 200 张卡** → 每卡一个上下文必撞浏览器 16 个的上限，模板内嵌 canvas 会让 400 个节点常驻。
所以：`fxMount()` 只建 1 个 canvas 放 `.card-fx-host`（fixed 移到屏外），进卡时 `insertBefore`
到 `.card-swatch` 首位（z-index:0，在精灵图 1 / 角标 2 / 操作条 4 之下，`overflow:hidden` 负责裁剪圆角），
离开移回宿主。canvas 换父节点时 WebGL 上下文保留。

### 三条调研得来的硬约束（写之前差点踩）
- `check-views.js:489` 的 **12.10** 有 `!/addEventListener\('pointermove'/` 反向断言 →
  坐标只能用 `card.onpointermove = fxOnMove` 属性赋值。
- `normalizeItem`（4305）把颜色写死成 6 位 hex（否则 `#888888`）→ 三色从内存 `data` 按 `data-id` 取，
  **不要读 `getComputedStyle`**（Chrome 会把 `color-mix`/`oklch` 序列化成别的东西）。
- `<canvas>` 是 replaced element：只写 `inset:0` 会只盖左上角一块，必须显式 `width/height:100%`。

### 着色器要点
- 静止态双保险：canvas 不在卡片里 + `uProg<=0.0005` 直接 `vec4(0.0)`。
- 漫开 `edge = uProg*1.18 + 噪声`，`1.18-0.16 > 1.0` 且 `uMaxDist` 就是指针到最远角的距离 →
  满程必然盖住四角；末段 `calm` 把噪声收敛，避免噪声啃角。
- **smoothstep 一律升序传参**：`smoothstep(edge, edge-0.16, dist)` 在 GLSL ES 里是 UB。
- 内部不能只做径向渐变（试过，像模糊光晕）：两层 fbm 叠「团块」+ 等值线脉络 + 波前湿边。
- **同色系洪水的边界天然低对比**，加一圈「湿边」（波前内侧压深 + 一线亮边）才看得出漫开；
  满程时波前已在卡外，这圈必须 `front = 1-smoothstep(0.86,1,uProg)` 淡掉，否则留下无来由的暗环。
- 白/黑/灰三类极端：中性色（S<0.10）注入 `FX_GRAY_HUE=214` 冷色相；提亮/压深封顶 ±0.26；
  纯白没有更亮的去处 → 提亮档改冷色彩度；兜底保证 `max|hi-base|,|lo-base| ≥ 0.05`。

### 踩到的坑
- **Chromium 会在鼠标不动、底下 DOM 被换掉后自己补发 `pointerover`**。原本靠 `elementFromPoint`
  续接，结果这个假事件先到，把 `resume` 吞了 → 后台 renderAll（搜索防抖 / AMS 扣减）会让液体闪一次。
  解法：`fxPark(true)` 记 `resumeId`，`fxOnOver` 命中同一张卡就 `resume=true`。
- `detach()` 只 `fxPark()` 不清 `frozen`，导致测试里后续悬停全被 `fxEnter` 的 frozen 守卫挡掉。
- **PNG 截图的 sha1 不能用来比像素**：同一画面两次截图字节不同（编码差异），实测像素 `maxDiff=0`
  而哈希不等。改成在页面里 `drawImage` 解码后逐像素比，容差 maxDiff ≤ 1。
- 截图前必须把「悬停本身引起的视觉变化」冻住（`.card-edit-overlay` 淡入、卡片抬 1px、边框亮一档），
  否则比的是这些而不是洪水。隔离样式用完要摘掉，否则后面点不到操作条按钮。
- 色系墙里卡片的 `getBoundingClientRect().top` 可能已经滚出视口（y=878 > 900），
  鼠标移过去不会触发 —— 测试取卡要取首屏内的那张。

### 测试
- `check-views.js` 298 → **319**：新增第十四节 14.1–14.21（单例 / 静止透明 / 层级 / smoothstep 升序 /
  renderAll 兜底 / elementFromPoint / pointerover 委托 / 无全局 pointermove / 双降级守卫 /
  白·近黑·灰·高饱和四组颜色极值 / jsdom 无 WebGL 不抛错 / canvas 恒为 1）。
  jsdom 里 `getBoundingClientRect` 全 0，`fxEnter` 在申请上下文之前就返回了 —— 正好不惊动 jsdom 的 canvas 桩。
- 新增 `tests/visual-cardfx.js`（35 条）：readPixels 证明静止全透明、0.45 时 58 档 alpha 且四角未盖、
  满程四角 230、两张卡复用同一节点、悬停中 renderAll 自己找回同一张卡、横扫 20 张 creates 仍为 1、
  reduced-motion 彻底不做。headless 的 WebGL 必须带 `--enable-unsafe-swiftshader --use-angle=swiftshader`，
  拿不到 gl 要**显式报失败**，不能静默跳过。
- 全绿：node 11 份打点 1205 条；浏览器 42+36+41+32+**35**。

### 手动核对
深色/浅色 × 1440/390 × 网格/色系墙卡片密度都看过；迷你密度（18px 小卷）不触发（`creates` 不变）；
同列卡片尺寸相同，横扫 20 张只发生 1 次后备缓冲分配（只在 `canvas.width` 真的变了才写）。

## 耗材库存：按入库时间排序

需求一句话：「耗材库存支持按照入库时间来进行排序」。

### 设计
`sortMode` 从 2 档扩到 4 档：`default`（录入顺序，= data 数组序）/ `usage` / **`new`（入库新→旧）** / **`old`（入库旧→新）**。

- 「入库时间」是**一个按钮的两个方向**（`toggleTimeSort()` 连点翻向），不是两档单选。
  理由：抽屉那一行已经有「默认顺序 / 消耗高→低」，再塞两个时间档变四个按钮；
  而且「最近入库的在前」是绝对主用法，第二档只作反向核对。
  按钮文案随方向变（`入库 新→旧` / `入库 旧→新`），不用回抽屉确认当前状态。
- 从别的排序切过来一律先进 `new`（最近在前）。
- **无入库时间的条目两个方向都沉底**（`invTimeCmp` 里 null 直接返回 1/-1，不参与方向）。
  若让 null 参与比较，升序时一屏 migrated 老数据会顶到最前面，像一堆 1970 年的记录。
- 同一毫秒（批量导入）保录入原序 —— 靠 ES2019 的稳定排序，不另写 tiebreaker。

### 可见性（这条最关键）
排序字段看不见 = 功能不可验证。所以**只在时间排序时**：
- 卡片 `card-meta` 尾部加 `.card-when`（`10-28`，今年省年份、跨年 `25-3-5`），title 给完整时间；
- 列表行 `.list-brand` 后跟 `.list-when`（`· 10-28`）。
切回其它排序就消失，平时不占位置、不改卡片高度。等宽数字（`font-variant-numeric: tabular-nums`）。

### 顺手修的一处老 bug
`sortDefaultBtn` 的选中态原来写的是 `sortMode !== 'usage'` —— 只要不是消耗排序它就亮。
加了两档时间排序后，这会变成「默认顺序」和「入库」同时亮。改成 `=== 'default'`。

### 覆盖面
同一个比较器 `invTimeCmp` 同时喂给 `getFiltered()`（网格/列表）与 `famGroups()`（色系墙组内）。
色系墙**组序仍按色相轮**（那是索引不是排行），只有组内按时间。空心计数的 `moreFilterCount`
从 `sortMode === 'usage'` 改成 `!== 'default'`，时间排序也会让筛选徽标亮。

### 已知限制（数据模型层面，已告知用户）
`createdAt` 是**条目**创建时间。补货（qty 增加）不刷新它，所以「2024 年建、2026 年补 3 卷」的条目
按入库时间会排在 2024 年。时间报表里有 `restock` 事件可以拿到最近补货时间，要更准得改成
「最近一次 add/restock 事件时间」，但会引入 flLog 依赖与老数据缺 log 的不一致，这轮没做。

### 测试
- `check-views.js` 319 → **344**：新增第十五节 15.1–15.25（sortMode 取值域 / setSortMode 白名单 /
  getFiltered 分支 / null 沉底 / 按钮与 toggleTimeSort / 徽标口径 / default 选中态 /
  card-when 条件渲染 / 组内排序 / list-when 十条静态护栏 + 实测排序 15 条）
- 实测覆盖：new 与 old 的完整顺序、未知时间两方向沉底、切回 default 不残留时间序、
  card-when 数量 = 有时间戳的条数、跨年补年份、空值不显示 1970、同批次稳定、reset 复位
- 12.72 的断言跟着 `!== 'default'` 更新（不是放宽）；node 共 **1230** 条 + 浏览器 186 条全绿

## 七、修「点回顶网页会闪」

### 现象与定位
用户报：点右下角「回到顶部」，网页会闪动。用 CDP screencast + 页内 rAF 逐帧采样
（`y` / `.pinned` 高度 / `is-tight` / `--pinned-h` / 文档高度 / 内容砖块相对位置）复现：

基准轨迹（1280×860，从 y=1600 平滑回顶）三次运行都一样：
```
翻转点 y=165, y=22, y=61   正向回弹 2 次（118→168）   文档高度 2051 ↔ 2116
```
即紧凑态在最后 200px 里**连翻三次**，每次翻都让内容跳 65px。

根因（不是 CSS 语法问题，是自激回路）：
1. `paintPinned` 用**单阈值** `tight = y > 120`；
2. 紧凑态把 `.pinned` 从 155px 压到 90px（实测高度差 65.25px）；
3. `.pinned` 横在滚动锚点上方，高度一变 → 浏览器**滚动锚定**为「视觉不跳」把 scrollY
   反向补偿（118 → 168）；
4. 补偿后的 y 又落回 `>120` → 判定翻回紧凑态 → 高度再变 → 再补偿……在阈值附近横跳。

### 修法（三处，缺一不可）
1. **迟滞**：进 `PIN_TIGHT_ON=120`，出 `120 - pinDelta - 16`。`pinDelta` 不再写死，
   在翻转前后各量一次 `getBoundingClientRect().height` 得到，且只取**见过的最大值**
   （估小会继续抖）。下限写 `Math.max(0, …)` 而不是 24：万一某页高度差 >96，24 的下限
   会让「补偿后位置」又落回进入区。
2. **回顶期间冻结紧凑态**：`jumpTop()` 里 `pinFreeze = pinTight`，`paintPinned` 只在
   `pinFreeze !== null` 时无条件用它；落到 `y<=1` 才解冻，让「展开」发生在静止的顶部，
   而不是滚动途中。解冻出口共四个：`y<=1`、`scrollend`、`wheel`、`touchstart`、`keydown`
   （后三个是打断保护，否则会卡在紧凑态），监听带 `capture:true`、`passive:true`。
3. **落地钉回 0**：展开会把下面内容推下 65px，滚动锚定顺势把 scrollY 顶到 ~65 ——
   「回到顶部」会停在离顶 65px 处。改完 class 立刻 `window.scrollTo(0,0)` 才盖得住。

### 为什么不用「回顶改 instant」
试过 `behavior:'auto'`：确实零闪（单帧最大位移 0），但丢掉平滑滚动不值。
也试过 `html{overflow-anchor:none}` / `.pinned{overflow-anchor:none}`：前者只减不除，
后者反而更糟（3 次翻转，锚点转移到下方内容，照样补偿）。

### 验收
- 修复后：翻转 **1 次（点在 y=0）**、正向回弹 **0**、终值 y=0。1440/1280/760 × 库存/色卡库/统计
  五组全一致。手动滚轮慢速上下穿阈值也只翻 1 次。
- `visual-sticky.js` ④ 加逐帧采样断言（4e–4k）：帧数>30、只翻一次、零回弹、`pinDelta>60`、
  落地 scrollY≤2。36 → **40** 条。
- `check-views.js` 加 12.63a–g 静态护栏（迟滞公式、实测高度差、冻结与解冻出口、落地写 0）。
  344 → **351** 条；node 合计 **1237** 条，浏览器 5 套 186 条全绿。
- 各页实测高度差：库存 65.25px，色卡库 / 统计 / 数据 / 打印机均为 0（那几页的 `.pinned`
  里没有 `.stat-card`，紧凑态规则不生效，天然不会抖）。
