## 这是什么？

如果你有一堆 3D 打印耗材，却总是记不清「这卷料盘还剩多少」「上次买的那个颜色叫什么」「某种材质还有库存没」——这个工具就是为你准备的。

**核心特点：**

- **零安装**：一个 `.html` 文件，浏览器打开直接用，无需服务器
- **数据本地**：所有数据存在浏览器的 `localStorage`，不联网，不上传
- **拓竹专属**：内置 199 种拓竹（Bambu Lab）官方耗材数据，输入编号自动识别颜色/材质
- **标签系统**：给耗材打标签（如「常用」「哑光」「柔性」），快速分类筛选
- **数据统计**：品牌/材质/色系/标签/规格多维度图表，支持环形图、条形图、数据表切换与 CSV 导出
- **时间报表**：什么时候加了什么耗材（按天分组的入库时间线）、什么时候用了多少（按天/按卷的消耗明细）

**三种用法，按需要选：**

| 用法      | 怎么起                                                      | 数据在哪                                   |
| ------- | -------------------------------------------------------- | -------------------------------------- |
| 纯前端     | 双击 `web/filament-manager.html`                           | 浏览器 `localStorage`（换机器不跟着走）           |
| 本地服务    | `npm install` → `npm start` → 打开 `http://127.0.0.1:8787` | **`data/store/*.json`**（权威）+ localStorage 缓存 |
| 容器（NAS） | `docker compose up -d --build`                           | **`./data/store/*.json`**（挂载项目目录）      |

> 只有「打印机页」（自动搜打印机、切片用量扣减、拓竹云）需要后台服务；  
> 库存、色卡、统计三个页签双击 HTML 就能用。
>
> **想让库存也存在文件里，必须跑后台服务** —— 浏览器出于安全限制不能直接读写磁盘文件。
> 跑起来后 `data/` 目录就是唯一权威数据源，多台设备看到的是同一份库存。

## 快速上手

### 1. 打开应用

直接打开 `web/filament-manager.html`，或用浏览器访问本地服务：

```
# 或者 clone 整个仓库
git clone https://github.com/your-username/filament-manager.git
cd filament-manager
npm install
npm start          # 等同 node server/printer-agent.js
# 打开 http://127.0.0.1:8787/
```

### 2. 添加第一条耗材

点击右上角 **「添加耗材」** 按钮：

- **颜色名称**：随便起个你好记的名字（如「樱花粉」）
- **拓竹编号**（可选）：输入 5 位数字编号（如 `16103`），会自动填充官方颜色和材质
- **品牌**：内置 41 个品牌关键词库（拓竹 / 三绿 / 兰博 / 阿米阿米 / **锐造新材** / eSUN / Polymaker …），
  认全称、简称、拼音、英文名和店铺名；填别的品牌也行，只是不会自动联想
- **材质**：PLA / PETG / ABS / TPU 等
- **颜色**：手动选色，或由编号自动填充
- **重量 / 数量 / 是否有料盘**：按实际情况填写

### 3. 批量导入（推荐）

如果你手头有一批耗材要一次性录入，点击 **「批量添加」**：

1. 在文本框里每行输入一条耗材名称，支持直接粘贴：
   ```
   白色 16103
   PETG 黑色 30105
   哑光海蓝 11600
   自定义颜色名
   ```
2. 带有拓竹 5 位编号的会自动识别颜色和材质
3. 点击 **「下一步：确认」** 预览解析结果
4. 在确认面板里可以调整颜色、品牌，删除不想要的条目
5. 点击 **「全部添加」** 完成导入

### 4. 筛选和搜索

- **搜索框**：输入耗材名称或品牌名关键词
- **材质筛选**：点击 PLA / PETG / ABS 等按钮
- **标签筛选**：点击自定义标签快速过滤
- **库存状态**：「有库存」筛出数量 > 0 的，「无料盘」筛出料盘已用完的

### 5. 编辑和管理

- 点击右上角 **「编辑」** 开启编辑模式，卡片上的名称/数量/品牌可直接点击修改
- 长按或勾选卡片可多选，然后批量删除
- 点击 **「标签」** 管理你的标签库，可以新增/删除/改颜色

## 技术实现

前端仍然是一个 HTML 文件（`web/filament-manager.html`），零框架、零外链、双击可用；  
后台服务（`server/`）只在需要连打印机、多设备共享库存时才会用到，两者可以完全独立运行。

### 数据存储

纯前端模式下，所有耗材数据存在浏览器 `localStorage`，key 为 `filaments`，每次修改立即持久化。

> **走后台服务时（`npm start` / 容器），服务端才是权威副本**：每个数据键写成
> `data/store/<键名>.json` 一个文件（容器里是 `/data/store/`），多台设备看到同一份库存；
> 浏览器 localStorage 退化为缓存。纯前端模式不碰服务端，仍然只用 localStorage。
>
> 为什么不做成「浏览器直接读写 data/ 目录」：浏览器没有这个权限，
> 唯一可行的路径是用 File System Access API 让用户手点授权目录，体验远差于跑一个常驻进程。

```javascript
// 保存
localStorage.setItem('filaments', JSON.stringify(data));

// 读取
const data = JSON.parse(localStorage.getItem('filaments') || '[]');
```

### 核心数据结构

每条耗材记录是一个 JS 对象：

```javascript
{
  id: 1,
  name: '玉白',          // 颜色名称
  bambuCode: '10100',    // 拓竹官方编号（可选）
  brand: '拓竹',         // 品牌
  material: 'PLA',       // 材质
  color: '#FFFFFF',      // 颜色 Hex 值
  weight: 1000,          // 重量（克）
  qty: 3,                // 数量（卷）
  hasSpool: true,        // 是否有料盘
  tags: ['基础色', '常用'] // 标签数组
}
```

### 拓竹编号数据库

内置一个静态数组 `bambuFilaments`，共 199 条记录，每条格式为：

```javascript
["10100", "Jade White", "#FFFFFF", "PLA Basic"]
//  编号      英文名        颜色Hex     所属系列
```

同时有一个 `bambuNameCn` 映射对象，把英文名转为中文（如 `"Jade White" → "玉白"`）。

### 批量解析逻辑

批量添加时，每行文字通过正则 `/^(.*?)(\d{5})$/` 匹配，提取末尾的 5 位数字作为拓竹编号，然后在 `bambuByCode` 字典中查找对应的颜色/材质信息。

```javascript
const m = s.match(/^(.*?)(\d{5})$/);
if (m) {
  const code = m[2];
  const filament = bambuByCode[code]; // 查数据库
  // 自动填充颜色、材质、中文名称
}
```

### 界面渲染

整个 UI 通过纯 JS 动态渲染，没有使用任何前端框架：

- `renderAll()` — 主渲染入口，每次数据变化时调用。开头做两件事：`closeSpoolPop()`（重建会换掉
  浮层的锚点按钮）和记下 `keepY`（清空 `innerHTML` 时页面瞬间塌高，浏览器会把 `scrollY` 夹到 0，
  表现为「勾一张卡就跳回顶部」；渲染完在确实变小时补回）
- `statJump(k)` / `resetInvFilters()` — 统计卡下钻：前三张落到筛选结果，「总重量 / 有料盘」去统计页；
  「总数」走重置（同时清颜色与搜索框 —— 只清筛选不清搜索是最常见的「点了我以为变了」）
- `toggleFilterDrawer()` / `refreshFilterDrawer()` — 「筛选」抽屉。绝对定位，展开时既不推内容也不改吸顶
  高度；徽标只数抽屉里的 6 个条件（颜色自己带徽标，两边都算会让人以为徽标是总数）
- `renderGrid()` / `renderList()` / `renderFam()` — 分别渲染网格、列表、色系视图
  （卡片模板抽成 `filamentCardHtml()`，网格与「卡片」密度共用同一份，勾选/编辑模式/角标才不会走样；
   `renderFam()` 渲染的是**瀑布流砖墙**：每个色系一块砖，砖内用 `spoolChipHtml()` 渲染迷你卷，
   **永远渲染全量**（没有截断、没有「还有 N 卷」、砖身没有第二层可展开），末尾同步调 `packFamWall()`；
   **没有任何 hover 触发的展开**；顶栏「迷你 / 卡片」切 `fmFamDensity`（设备本地偏好））
- 砖头 = **色系标牌**（三重族色标识，解决「12 块砖糊成一片白卡」）：
  ① 砖头底色 `color-mix(in oklch, var(--fam) 16%, var(--bg-2))` —— 12 块砖头部成为 12 个色调
  （11% 时实测 oklch L 全在 0.94–0.98，量不出差异，所以定在 16%）；
  ② 顶部 `inset 0 3px 0 var(--fam)` 压一道族色线（inset shadow 跟随外壳圆角，不用额外元素）；
  ③ 砖框 `border: color-mix(in oklch, var(--fam) 24%, var(--border))` —— 扫视靠外轮廓。
  外加 5×26px 族色色标（旧版 3×20，在 52px 高的砖头里细到看不见）。
  系名拆成「主名 1.02rem/700」+ 小号灰字「色系」：旧版整串 0.9rem/600 且 `letter-spacing: 0.12em`，
  中文字距拉开只是把标题稀释成几根散开的笔画。**白色系单独走描边表达** ——
  `#f2f2f2` 混进近乎纯白的底还是白，强行上色等于骗人，改用中性灰顶线 + 加重砖框
- `packFamWall()` — 把砖按「算出来的瀑布流」落位，三件事依次做：
  ① 按容器宽算列数（`FAM_MIN_COL` 292、上限 4）并给每块砖定宽量高，高宽比超 `FAM_ASPECT.mini`（1.6）
  就把砖从 1 列加宽到 2 列。**加宽只对「迷你」密度开放，且要 3 列以上** —— 卡片是按砖宽填满的，
  砖一宽卡就宽，同一面墙上两种卡宽是「乱」的根源；2 列时加宽等于独占整行，砖墙会退化成横幅；
  ② 落位用 `score = top + 空洞`（空洞 = 跨列盖住的各列最高值之差 × span），若必然留洞且竖放不把墙顶得更高，
  就退回 1 列；③ 全部坐标写完才加 `.is-packed`（此前砖走普通文档流，脚本出错只是退化成竖排，不会叠在一起）。
  重排靠 `scheduleFamPack()`（resize → `requestAnimationFrame` 合并）+ `document.fonts.ready` 补一次，
  **砖上不挂 ResizeObserver**（会自激）
- `famFlash()` — 统计页按色系跳转时的落点脉冲（`.is-hit`，1400ms）
- `paintChrome()` / `paintPinned()` — 吸顶栈。前者把 header 与页签的**实测**高度写进 `--chrome-h` / `--tabs-h`
  （窄屏 header 会换行长到 110px，写死 60px 会让页签钻到它底下），后者在 rAF 里统一算
  「是否紧凑态 / 是否已吸住 / 回到顶部按钮显隐」，避免每个 scroll 事件都读一次 rect。
  `ResizeObserver` 只盯 header 与页签本身（resize 事件抓不到「窗口没动、header 却换行了」）
- `paintPinnedH()` — 把当前可见页的工作台高度写进 `--pinned-h`。色卡库的分组标题要贴在它下沿，
  而它随「已选筛选」胶囊条出现而变；窄屏 `.pinned` 是 static，写 0 让组标题直接贴页签
- `swGroupsHtml()` / `swGroupHtml()` / `swToggleGroup()` — 色卡库按色系分组。每组默认摊开
  `SW_GROUP_PREVIEW = 12` 张，组标题里放「展开其余 N 个」；搜索时 `forceOpen` 全展开。
  卡片仍带**全局** `data-i`，所以 `openSwModal(i)` / `swToggleFav(i)` 不用改
- `stNameIdx()` / `stNameColor()` — 品牌与材质按**名字**定色（品牌查 `brandDB` 位次、材质查
  `ST_MAT_ORDER` 枚举），不再用 `ST_PALETTE[排序后的下标]`，否则换个口径同一个品牌就换颜色
- `openSwBrands()` / `closeSwBrands()` — 品牌名录弹层，管焦点进出（关掉后回到入口按钮）
- `prnRecheckAgent()` — 离线态「重新检测服务」的唯一入口，重探后必给一条 toast 反馈
- `jumpTop()` — 回到顶部；平滑滚动受 `prefers-reduced-motion` 约束，并把焦点交给 `#main`
  （按钮滚走后焦点掉到 body，键盘用户得从头 Tab 一遍）。跳之前把紧凑态冻在当前值
  （`pinFreeze`），落地 `y<=1` 才解冻 —— 否则滚动途中翻一次紧凑态就是一次 65px 的内容跳变
- 紧凑态阈值有**迟滞**：进 `PIN_TIGHT_ON=120`、出 `120 - pinDelta - 16`（`pinDelta` 是翻转前后
  实测的高度差）。单阈值会自激：改 `.pinned` 高度 → 浏览器滚动锚定反向补偿 scrollY →
  判定翻回去 → 再改回来，肉眼就是「回顶时闪两下」。落地后还要 `scrollTo(0,0)` 把锚定的
  补偿顶回去，否则回顶会停在离顶部 ~65px 处
- `openSpoolPop()` / `closeSpoolPop()` — 点迷你卷弹出的锚定详情浮层（fixed 定位、翻边、四边夹进视口）；
  关闭时机：外部 pointerdown / Esc / 页面滚动 / `renderAll()`
- `setView()` / `applyView()` — 切视图；`fmDefaultView` 是**设备本地**偏好，不进同步也不进备份
- `applyTheme()` / `setTheme()` — 全局「亮 / 暗」主题，只改 `<html data-theme>`，不重渲染；
  `fmTheme` 同样只存本地（字体仍是系统栈，零外链，断网与 NAS 内网都能开）
- `renderStats()` — 更新顶部统计栏
- `renderMaterialFilters()` / `renderTagFilters()` — 动态生成筛选按钮

## 数据备份与迁移

数据存在 `localStorage`，换浏览器、清缓存、换电脑后数据不会跟着走。所以页面顶部有第四个标签页 **「数据管理」**，备份和恢复都在里面完成，不需要打开开发者工具。

**备份**：点「导出 JSON 备份」，会下载一个 `耗材库存_备份_日期.json`，包含耗材、标签池、色卡收藏三部分。换设备时在新机器上打开本工具 → 数据管理 → 拖入这个 JSON → 选「替换全部」即可。

**导入**支持 JSON 与 CSV 两种，导入前会先列出解析结果（新增几条、重复几条），可切换三种模式：

| 模式   | 行为                       |
| ---- | ------------------------ |
| 跳过重复 | 只导入本地没有的，已存在的保持原样        |
| 数量累加 | 已存在的把卷数相加，适合补录同一批货       |
| 替换全部 | 清空现有库存，完全用文件替换（旧数据先进回收站） |

**误删不用慌**：删除耗材、批量删除、清理用完（在「数据管理 · 危险操作」里，不再挨着筛选行的「已用完」）、清空全部，都会先放进回收站（保留最近 60 条），随时可单条还原或全部还原。

> 仍然可以用开发者工具手动读写：Console 里 `copy(localStorage.getItem('filaments'))` 导出，  
> `localStorage.setItem('filaments', '【备份JSON】')` 后刷新即可恢复。

### 服务端模式：数据就是一个目录

跑起后台服务后，所有数据都在项目目录的 `data/` 下，**一个键一个文件**，打开就能读：

```
data/
├── store/                    ← 页面里的库存 / 标签 / 匹配账本等（可整体备份）
│   ├── _meta.json            各键版本号，不含数据本体（别手改）
│   ├── filaments.json        库存数组  ← 最常看/改的就是它
│   ├── savedTags.json        标签池
│   ├── lowStockCfg.json      低库存阈值
│   ├── prnSlotMatch.json     槽位匹配账本
│   ├── prnTagBind.json       RFID 绑定表
│   ├── prnCalibLog.json      校准流水
│   └── …                     其余键同理，文件名 = 浏览器 localStorage 的 key
├── printer.config.json      打印机列表（含明文访问码，注意权限）
├── bambu-cloud.json         拓竹云 token（0600）
└── printer-history.json     任务历史（切片用量原始数据）
```

`filaments.json` 的内容就是库存数组本身，没有嵌套转义：

```json
[{"id":1,"name":"哑光浅灰","brand":"锐造新材","material":"PLA","color":"#B8BAB6","weight":1000,"qty":1}]
```

| 想做的事 | 怎么做 |
| --- | --- |
| 备份 | 拷走整个 `data/` 目录（或只拷 `data/store/`） |
| 搬到另一台机器 | 项目目录 + `data/` 一起拷，起服务即可 |
| 手动改库存 | 编辑 `data/store/filaments.json` → **重启服务**（运行中改了会被下次写入覆盖） |
| 看数据在哪 | 页面「数据管理」页有一张「数据存放位置」卡片，列出真实路径与文件清单；或 `GET /api/store?info=1` |
| 整库导出 | `GET /api/store/export` 出一个合并的 JSON |

容器里 `data/` 被挂载成 `/data`，所以宿主机上的路径就是**项目目录下的 `data/`**，
`docker-compose.yml` 已写成 `- ./data:/data`。首次启动前必须给容器用户（uid 1000）写权限：

```bash
mkdir -p ./data && chown -R 1000:1000 ./data
```

> **从旧版本的命名卷升级**：老部署把数据放在命名卷 `fm-data` 里，不在项目目录。
> 换成 `./data` 之后页面会显示空库 —— 先把数据掏出来，再删旧卷：
>
> ```bash
> docker run --rm -v filament-manager_fm-data:/from -v "$PWD/data:/to" \
>   alpine sh -c 'cp -av /from/. /to/'
> docker compose up -d
> # 确认页面数据都在之后
> docker volume rm filament-manager_fm-data
> ```
>
> 旧格式 `app-store.json`（单文件、值二次转义）会在启动时自动拆成 `store/*.json`，
> 原文件改名成 `app-store.json.migrated-<时间戳>` 留底，不会丢数据。
